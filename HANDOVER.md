# SintetikMedia — лендинг и форма. Инструкция для продолжения работы

Этот документ описывает проект целиком, чтобы Claude в другом аккаунте (или другой человек) мог продолжить работу без потери контекста. Всё, что нужно, лежит в архиве `sintetikmedia.zip` в папке `output_project/`.

---

## 1. Что это за проект

Лендинг сервиса **SintetikMedia** — AI-автоматизация ведения каналов в MAX и Telegram (от идеи до готового поста с картинкой). Плюс отдельная страница-форма заявки на демо, интегрированная с CRM «Клиентская база» (clientbase.ru).

Домен: **sintetikmedia.ru**. Хостинг поддерживает **PHP** (в корне лежат PHP-файлы).

## 6. Логика чекбокса согласия (важная механика)

На лендинге три чекбокса «Я принимаю условия оферты и ознакомлен(а) с политикой обработки персональных данных» (ссылки на oferta.html и policy.html). Отметка + переход в бот = акцепт оферты (п. 4.1 оферты). Кнопки MAX/Telegram **заблокированы** пока галочка не стоит.

**Как работает (index.html + main.js):**
- Кнопки имеют класс `btn-consent` и атрибут `data-consent="heroAgree|pricingAgree|finalAgree"`, стартуют с `aria-disabled="true"`
- Кнопка в шапке имеет `data-scroll-consent="heroConsent"` (скроллит к Hero-чекбоксу)
- При клике без галочки: `preventDefault()` + `stopImmediatePropagation()` → переход блокируется, чекбокс трясётся и краснеет (классы `consent-shake` + `consent-highlight`)
- Когда галочка отмечена: `aria-disabled="false"`, кнопка работает, переход происходит, отправляется цель в Метрику

**КРИТИЧНО:** все кнопки MAX и Telegram обрабатываются ОДНИМ обработчиком в main.js (`a[href*="max.ru"], a[href*="t.me"]`), который совмещает: проверку чекбокса, тряску и отправку в Метрику. НЕ делать отдельные обработчики на Метрику — иначе переход происходит в обход проверки чекбокса (была такая ошибка).

**CSS чекбокса:** `.btn-consent[aria-disabled="true"]` — только `opacity: .5`, БЕЗ `pointer-events: none` (иначе клик не долетит до JS и тряска не сработает).

## 7. Форма заявки на демо (form.html + cb_proxy.php)

### Назначение
Персональные ссылки клиентам вида:
```
sintetikmedia.ru/form.html?clientbase_hash=XXXXX
```
Форма открывается **предзаполненной** данными клиента из «Клиентской базы», при отправке ответ привязывается к тому же клиенту.

### Интеграция с «Клиентской базой»
- Анкета в КБ: `clientbase_id=60`, `qst_id=60`
- Endpoint: `https://sintetik.clientbase.ru/questionare.php`
- Соответствие полей формы → ID полей в КБ:
  | Поле формы | ID в clientbase |
  |---|---|
  | f_email (Email) | k_input_field_60_17860 |
  | f_company (Компания) | k_input_field_60_17890 |
  | f_site (Сайт) | k_input_field_60_17900 |
  | f_name (Контактное лицо) | k_input_field_60_18100 |
  | f_wishes (Пожелания) | k_input_field_60_18110 |
  | f_phone (Телефон) | k_input_field_60_18120 |

### Как работает предзаполнение (обход CORS)
1. form.html читает `clientbase_hash` из URL (и обрезает финальную точку, если есть)
2. Делает `fetch('cb_proxy.php?hash=XXX')` — запрос на СВОЙ домен, CORS не мешает
3. **cb_proxy.php** на сервере делает server-to-server запрос (cURL) к clientbase с `ajax_call=1&hash=XXX`, возвращает JSON
4. form.html заполняет поля из `qst_fields` / `linked_values`

### Отправка формы
- Через скрытую `<form>` в невидимый `<iframe name="k_frame_upload_60">` (механика самой КБ)
- Хэш передаётся обратно полем `hash` → ответ привязывается к клиенту
- Передаются UTM-метки из URL (`utm_href`)
- После отправки показывается экран «Заявка отправлена!»

### Согласия в форме (с 21.09.2026)
- Три отдельных чекбокса: `f_agree_offer` (оферта, обязательно), `f_agree_pdn` (согласие на ПДн → consent.html, обязательно), `f_agree_ads` (реклама → consent-ads.html, необязательно). Ни один не отмечен по умолчанию.
- Кнопка `kSubmit` — `aria-disabled="true"`, пока не отмечены оба обязательных (не `disabled`, чтобы клик доходил до JS и чекбокс подсвечивался).
- В КБ дополнительно уходят скрытые поля: `consent_offer`, `consent_pdn`, `consent_ads`, `consent_version` (дата редакции текстов, константа `CONSENT_VERSION`), `consent_time`, `page_url`, `form_name`. **В анкете 60 нужно завести поля с этими именами**, иначе КБ их не сохранит.
- При изменении текста оферты или согласий — поменять дату редакции в документе и `CONSENT_VERSION` в form.html.

### Что проверить при деплое формы
1. **cURL включён** в PHP на сервере (для cb_proxy.php). Если нет — заменить на `file_get_contents` с stream context.
2. **Домен в cb_proxy.php** — переменная `$allowed_origin = 'https://sintetikmedia.ru'`. Поправить, если тестируется с www или поддомена.
3. **Хэш для ajax_call** — убедиться, что хэш из ссылки просмотра анкеты подходит и для режима предзаполнения `ajax_call=1`. В некоторых конфигурациях КБ это разные хэши — если данные не подтягиваются, проверить у платформы.
4. **Ответ clientbase внутри iframe** — с чужого домена JS не читает содержимое iframe, поэтому подтверждение показывается по таймеру после отправки, а не по факту ответа сервера.

## 8. Рабочие правила и подводные камни (накопленный опыт)

- **Полный код без сокращений.** Марат просит всегда выдавать полный готовый к копированию код, без фрагментов с `...` и плейсхолдерами.
- **НЕ встраивать картинки в base64** — держать отдельными файлами (см. п.2).
- **Reveal-анимация:** элементы с классом `.reveal` стартуют с `opacity:0` и появляются по IntersectionObserver. У Hero есть override `.hero .reveal { opacity:1 }` — Hero виден сразу, не зависит от скролла (иначе при некоторых условиях главный экран оставался пустым).
- **Иконки в секциях how и autopilot** — это inline SVG (обёрнуты размером через CSS `.step-icon svg { width:28px; height:28px }`), НЕ эмодзи. При правках не заменять на эмодзи.
- **Оригинальный проект** был на отдельных css/js/images. Если пользователь загрузит новый исходный архив — брать ассеты (логотипы, картинки, SVG-иконки) из него, не подставлять свои заглушки.
- **Контейнер Claude сбрасывается** между сессиями — восстанавливать проект из `sintetikmedia.zip` командой `unzip -o`.

## 9. Как продолжить работу в новом аккаунте

1. Загрузить `sintetikmedia.zip` в чат
2. Распаковать: рабочая папка — `output_project/`

4. Вносить правки в `index.html` / `form.html` / `css/style.css` / `js/main.js`
5. Пересобирать zip для выдачи:
   ```bash
   cd /home/claude && rm -f output.zip && zip -r output.zip output_project/
   ```
6. Для превью в чате — показывать отдельный HTML через артефакт (но помнить: относительные пути к css/images в артефакте не работают, картинки не отобразятся; для полноценного просмотра — только скачивание архива и открытие локально).
